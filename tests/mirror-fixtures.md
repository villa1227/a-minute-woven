# Mirror test images and checks

`test_mirror.cjs` generates geometric images in memory. `check_mirror_browser.cjs` generates camera-like red/blue frames, a JPEG with EXIF Orientation=6, and a larger image with elliptical outlines. These are synthetic and contain no participant images. The camera is simulated with Canvas captureStream; it does not request the user's physical camera.

Optional visual QA portrait: public photograph of Grace Hopper, distributed as Matplotlib sample data `grace_hopper.jpg`. Source: https://github.com/matplotlib/matplotlib/blob/v3.10.0/lib/matplotlib/mpl-data/sample_data/grace_hopper.jpg . Upstream attribution: https://github.com/matplotlib/matplotlib/blob/v3.10.0/lib/matplotlib/mpl-data/sample_data/README.txt ; the image is a public-domain U.S. Navy photograph. A local installed Matplotlib sample can be copied for QA, avoiding any network dependency. It is a public test photograph, not a participant's capture. Do not infer emotional or physiological attributes from it.

To repeat visual QA, copy that public fixture into the ignored `diagnostics/mirror/grace_hopper.jpg`, then start the mirror server and run the optional browser check. It saves three detail variants, a desktop screenshot and a mobile screenshot only under `diagnostics/mirror/`. No fixture, portrait output or participant photos are added to Git. If this optional fixture is absent, generated-image tests still run and report `portraitChecked:false`.

Inspect eyes/nose/mouth, face outline, hair texture, background edges and white gaps. This is edge extraction, not semantic portrait illustration; background and clothing edges remain. Compare simple/standard/rich and confirm increased line width does not fill the face.

2026-11-07 local QA: the bundled Grace Hopper public sample was inspected at 512×600. All three final presets retain visible eyes/glasses, nose, mouth and head/shoulder boundaries; simple suppresses most skin/clothing texture, while rich keeps more background texture. At 1 px line width the outputs contained approximately 10,240 / 14,859 / 50,058 black pixels respectively, with ~110 ms worker processing in this run. The generated 1600×1200 workload allowed more than 15 main-thread animation frames during processing. These are one-machine observations, not a universal performance guarantee. Physical camera framing and actual portrait likeness still need checking with the installation hardware; automated capture checks used synthetic streams.

Additional manual-control QA: `minimal` retained about 4,705 black pixels on the same public portrait, less than the original `simple` preset. This deliberately discards more facial detail. Browser checks also cover number/slider synchronization, actual pixel changes under manual thresholds, preset reset and switching, and unchanged default results for the three existing presets. Automatic presets are not guaranteed to have strictly ordered edge counts on every image.

Background edition QA uses the same public Grace Hopper portrait, synthetic four-channel fixture and matching horizontal pen paths in both editions. It writes `background-portrait-artwork.png`, `legacy-portrait-comparison.png`, desktop/mobile screenshots and a synthetic composited artwork under ignored diagnostics/mirror/. These are artificial demonstrations, not physiological measurements of the photographed person. Final preset for the comparison is standard; default background diameter is 6%. Tests also use 16% diameter for layer intersection assertions and 512 px brush diameter for cache/performance checks.
